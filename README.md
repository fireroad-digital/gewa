# GEWA Dealer Widgets

Embeddable iframe widgets providing an interactive dealer map and a dealer listing for GEWA brand networks. Hosted as static files on GitHub Pages; no backend required.

**Current brands:** Ovation · Arcus · Müsing

---

## How It Works

Each brand has two embeddable iframes:

| Widget | URL pattern |
|--------|-------------|
| Map | `https://fireroad-digital.github.io/gewa/{brand}/mapbox/gewa-mapbox-{brand}.html` |
| Listings | `https://fireroad-digital.github.io/gewa/{brand}/dealers/gewa-dealers-{brand}.html` |

Both widgets load dealer data from a pre-processed JSON file at `/data/{brand}.json`. That file is generated by a geocoding script and committed to the repo. A scheduled GitHub Action regenerates it daily from the client's Google Sheet.

```
Google Sheet (client edits) → GitHub Action → data/{brand}.json → widgets
```

## Dealer Data

### Source

All dealer data lives in a single Google Sheet:

`https://docs.google.com/spreadsheets/d/144WlLQQWkf-D2EarT_dayZWzAX9i4xSxZLCHZePDx54`

Each brand occupies its own tab (Ovation, Arcus, Müsing).

### Geocoding

The geocoding script reads each tab, geocodes any new or changed addresses using [Nominatim](https://nominatim.org/) (OpenStreetMap, free), and writes the result to `data/{brand}.json`. Existing entries are cached by address hash and skipped, so only new or changed rows trigger API calls.

**Run manually:**
```bash
cd scripts && npm install   # first time only
node geocode.js             # all brands
node geocode.js ovation     # single brand
```

**Automatic:** The GitHub Action at `.github/workflows/geocode.yml` runs daily at 6am UTC and commits any updates to `data/*.json`.

### Geocoding Notes

- Addresses must be in standard US format. Suite/unit numbers are automatically stripped before geocoding.
- Google Plus Codes (e.g. `56H5+Q6 Medina Township, OH`) are supported — the script decodes them via the Open Location Code library.
- Entries that fail geocoding are written to the JSON with `"_geocodeFailed": true` and `Latitude`/`Longitude` set to `null`. They appear in the dealer listing but not on the map.
- To manually supply coordinates for a failed entry, add `Latitude` and `Longitude` columns to the sheet row with decimal values. Update `clients.json` to map those columns, or edit `data/{brand}.json` directly and remove `_geocodeFailed`.

### Data Quality Issues

Common causes of geocoding failure:
- Business name contains an unquoted comma (e.g. `Acme Music, Inc.` must be `"Acme Music, Inc."` in the CSV before uploading to Sheets)
- No street number (road-only address)
- Unusual road name not in OpenStreetMap
- Wrong city name

## Adding a New Brand

1. **Create the Google Sheet tab** — add a new tab to the existing spreadsheet. Column requirements depend on address format:

   - **Split format** (address in separate columns): `Name`, `AddressLine1`, `AddressLine2`, `City`, `State`, `Zip Code`, `Phone Number`
   - **Single format** (full address in one column): `Company Name` (or col 0), `Address`, `Phone`, `Website`

2. **Add the brand to `scripts/clients.json`:**
   ```json
   {
     "id": "brandname",
     "sheetId": "144WlLQQWkf-D2EarT_dayZWzAX9i4xSxZLCHZePDx54",
     "sheetName": "BrandTabName",
     "country": "US",
     "addressFormat": "single",
     "columnMap": {
       "Name": "Company Name",
       "Phone": "Phone",
       "Address": "Address",
       "Website": "Website"
     }
   }
   ```

3. **Create the HTML entry points** by copying an existing brand's files and updating `GEWA_CONFIG`:

   `brandname/mapbox/gewa-mapbox-brandname.html`:
   ```html
   <script>
     window.GEWA_CONFIG = {
       dataUrl: 'https://fireroad-digital.github.io/gewa/data/brandname.json'
     };
   </script>
   ```

   `brandname/dealers/gewa-dealers-brandname.html`:
   ```html
   <script>
     window.GEWA_CONFIG = {
       dataUrl: 'https://fireroad-digital.github.io/gewa/data/brandname.json',
       title: 'Brand Dealers',
       fields: ['Phone', 'Website']   // omit 'Website' if the sheet has none
     };
   </script>
   ```

4. **Run the geocoding script** to generate `data/brandname.json`:
   ```bash
   node scripts/geocode.js brandname
   ```

5. **Commit and push** — GitHub Pages will serve the new entry points immediately.

## Testing

### Data validation

Validates all `data/*.json` files for structural correctness before committing. Catches missing coordinates, mismatched state abbreviations, duplicate address hashes, and malformed fields.

```bash
npm run validate
```

The daily geocoding GitHub Action runs this automatically after the geocoding step. If validation fails, the data is **not committed** and a Slack alert is sent. Exit code 0 = clean, 1 = failures.

### Unit tests

Tests the pure JavaScript functions in the widget source files (`renderDealer`, `dealersToGeoJSON`, `ensureHttp`). Uses Node's built-in test runner — no dependencies required.

```bash
npm test
```

## Build Process

**Build tool:** [CodeKit 3](https://codekitapp.com/) (Mac GUI app — no npm/webpack).

- Edit source files in `js/` and `css/`
- CodeKit minifies and outputs to `shared/v{version}/`
- Output paths must be set to `shared/v{version}/` for all four files

### Releasing a New Version

1. Edit `old_version` and `new_version` in `change_ver.sh`
2. Run `./change_ver.sh` — renames `shared/v{old}/` and updates all HTML asset references
3. In CodeKit, update the `GEWA_VERSION` environment variable (Project Settings => Environment Variables)
4. Rebuild in CodeKit
5. Commit and push

## Widget Configuration Reference

Both widgets read `window.GEWA_CONFIG` set in the HTML file before the widget script loads.

### Mapbox widget

| Key | Required | Description |
|-----|----------|-------------|
| `dataUrl` | Yes | URL to the brand's `data/{brand}.json` |
| `mapboxToken` | No | Override the default domain-restricted Mapbox token |

### Dealers widget

| Key | Required | Description |
|-----|----------|-------------|
| `dataUrl` | Yes | URL to the brand's `data/{brand}.json` |
| `title` | No | Overrides the `<h2>` heading text |
| `fields` | No | Array of optional fields to render. Supported values: `'Phone'`, `'Website'`, `'Email'`. Defaults to `['Phone', 'Website']` |

## Caching and Data Freshness

When the daily workflow commits updated dealer data to the `release` branch, changes propagate through three layers before end users see them:

| Layer | TTL / delay | Controllable? |
|-------|-------------|---------------|
| GitHub Pages rebuild | ~1–2 min after commit | No — Pages rebuilds automatically |
| GitHub Pages CDN (`max-age=600`) | Up to 10 min | No — GitHub sets these headers |
| Browser cache | Bypassed on every request | **Yes — handled in widget JS** |

### What we control

Both widgets pass `cache: false` to `$.ajax`, which appends a `?_={timestamp}` query parameter on every request. This prevents the browser from ever serving a stale cached response — the browser always asks the CDN for a fresh copy.

### What we can't control

The GitHub Pages CDN caches responses for up to 10 minutes regardless of the `cache: false` flag (that flag only affects the browser's own cache, not upstream caches). This means after a daily data commit there is an unavoidable window of up to ~12 minutes (Pages rebuild + CDN TTL) before all users see the updated data. For dealer listings that change at most once a day, this is acceptable.

### If you need to verify data is live

Check the raw JSON URL directly before testing the widgets:

```
https://fireroad-digital.github.io/gewa/data/ovation.json
```

If that URL still returns old data, the CDN hasn't refreshed yet — wait a few minutes and try again. Once it returns the new data, the widgets will reflect it on the next page load.

## Iframe Embedding

The client embeds the widgets on their site like this:

```html
<!-- Map -->
<iframe src="https://fireroad-digital.github.io/gewa/ovation/mapbox/gewa-mapbox-ovation.html"
        width="100%" height="500" frameborder="0"></iframe>

<!-- Dealer listings (height auto-adjusts via postMessage) -->
<iframe id="dealers-frame"
        src="https://fireroad-digital.github.io/gewa/ovation/dealers/gewa-dealers-ovation.html"
        width="100%" frameborder="0"></iframe>
<script>
  window.addEventListener('message', function (e) {
    if (e.data && e.data.type === 'GEWA_SET_HEIGHT') {
      document.getElementById('dealers-frame').style.height = e.data.data.height + 'px';
    }
  });
</script>
```

The dealers widget sends a `GEWA_SET_HEIGHT` postMessage after rendering so the parent page can size the iframe to fit the content.

## `data/{brand}.json` Format

```json
{
  "network": "arcus",
  "updatedAt": "2026-04-15T06:00:00.000Z",
  "dealers": [
    {
      "Name": "Anderson Violins",
      "AddressLine1": "210 Yale Avenue",
      "AddressLine2": null,
      "Address": "210 Yale Avenue, Swarthmore, PA 19081",
      "City": "Swarthmore",
      "State": "Pennsylvania",
      "StateAbb": "PA",
      "ZipCode": "19081",
      "Phone": "610-328-6448",
      "Website": ["www.andersonviolins.com"],
      "Latitude": 39.9015,
      "Longitude": -75.3521,
      "_addressHash": "a1b2c3d4e5f6"
    }
  ]
}
```

`Website` is always an array (even for single URLs). Entries with `_geocodeFailed: true` have `Latitude`/`Longitude` of `null` and are excluded from the map.
